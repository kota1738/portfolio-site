Backend · running2026

Distributed task queue API

An asynchronous job processing service. Clients submit work over REST and get a job id back immediately; separate worker processes claim and execute it, and every job is trackable through queued, running, succeeded, failed and cancelled. Job state and JSON results live in PostgreSQL, and Redis is only a wake up channel, so a broker outage delays work instead of losing it.

Workers claim atomically with SELECT … FOR UPDATE SKIP LOCKED plus a status guard, so concurrent workers never run the same job twice. Retries use exponential backoff with per job attempt limits, idempotency keys make client retries safe, and a lease reaper requeues jobs orphaned by a crashed worker. JWT bearer auth with per user job isolation; payloads are validated against the job type's schema before the row is written. 68 tests run in CI against real PostgreSQL and Redis.

Running on the home server as five containers with the API and database bound to loopback, so the monitoring stack can scrape its /metrics over a private Docker network without exposing a port.

Platform · deployed2026

Infrastructure monitoring and alerting

A seven container observability stack running on the home server: Prometheus, Alertmanager, Grafana, node_exporter, cAdvisor and blackbox_exporter, each under a memory limit so monitoring cannot starve the services it watches.

Thirteen alert rules cover the host, every container, the HTTP services and the task queue API's own metrics, with three provisioned dashboards in the repository rather than clicked together. All eight scrape targets are up, and delivery is proven, not assumed: a real disk space alert at 13% free fired and a hand fired test alert and its resolution both reached Discord. A deliberately permanent Watchdog alert exists because a silent pipeline and a healthy system look identical.

Infrastructure2024 — present

Self hosted Linux service stack

Fifteen containerised services on ARM64 Fedora with SELinux enforcing, defined in a single Docker Compose file. Egress for selected containers is policy routed through a Gluetun VPN gateway; Pi‑hole handles DNS filtering for the network; n8n runs scheduled automation. Backups run on a schedule with rsync.

Public services are exposed through a Cloudflare Tunnel — an outbound only connector, so there is no port forwarding and no inbound port open on the network. Rebuilds and redeploys are scripted end to end.
